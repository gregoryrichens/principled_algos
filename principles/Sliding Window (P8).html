Sliding Window

Grow the right edge. Shrink the left edge. Never start again from the beginning.

P2 is "running totals" and P5 is "two pointers that move toward each other". Card numbers refer to DRILLS.md.

As if to a child

You have a long row of colored beads. You want the longest run of beads, side by side, with no color two times. Hold a card with a slot over the row, so that you see only the beads in the slot.

Start at the left end. Make the slot wider on the right side, one bead at a time. If the new color is already in the slot, push the left side to the right until the old bead of that color goes out. Remember the biggest count of beads. The slot only moves to the right. At the end, the biggest count is the answer.

The extended explanation

Start from what is true

A stretch is a group of items side by side in a list, with no gaps: a substring in text, a subarray in numbers. Start with three facts.

  • Fact 1. A start and an end set each stretch. With n items there are n × (n + 1) ÷ 2 stretches: 36 for 8 letters. The slow way tests each one.
  • Fact 2. Neighbor stretches share almost everything. Keep notes: a small summary of the contents, for example a count of each letter. When an item comes in or goes out, change the notes for that item only.
  • Fact 3. For many rules, a bad stretch makes every bigger stretch bad. "abca" has a repeated letter, so every stretch that contains "abca" has that repeat too. Read backwards: every part of a good stretch is good. Programmers call this rule monotone.

Now join the facts. The window is the stretch from position l to position r, both included. Each step grows it (r moves right) or shrinks it (l moves right).

  • Why l never moves back. When the window is bad, Fact 3 says that every stretch from l to r or further is bad. The stretches from l that end before r are parts of the last good window, so they are not longer. So l is finished.
  • Why r never moves back. After l moves, you skip the stretches from the new l that end before r. They are also parts of the last good window, so they are shorter than a stretch you already recorded.

So each edge moves at most n times: 2n cheap steps in total.

The sentence that keeps the code correct

When the shrink loop ends, the window is the longest good stretch that ends at r, and the notes describe exactly the items inside it.

This sentence is the invariant: a statement that is true at the same point of every loop turn. The first half makes the answer correct: each end gets its longest good stretch, and the longest of those is the longest of all. The second half makes the code fast. If your loop builds the notes again from nothing, you have lost the window.

Worked example 1: Longest Substring Without Repeating Characters (LeetCode 3)

Problem. Return the length of the longest stretch of a string in which no character appears two times. For "abcabcbb" the answer is 3 ("abc"). The notes count each character in the window.

def lengthOfLongestSubstring(s):
    count = {}                       # notes: each character's count in s[l..r]
    l = 0
    best = 0
    for r, c in enumerate(s):
        count[c] = count.get(c, 0) + 1   # grow: s[r] comes in
        while count[c] > 1:          # bad: c is in the window two times
            count[s[l]] -= 1         # shrink: s[l] goes out, then l moves
            l += 1
        best = max(best, r - l + 1)  # good again: record
    return best

Each Next step click above is one loop turn: a grow is a for turn, a shrink is a while turn. The while loop moves l at most n times in total, so this loop inside a loop is not n × n work.

Napkin math: how much faster?

Assume 109 simple steps each second. The worst slow way builds a new set for every stretch. The better slow way, a double loop, keeps one set for each start.

By hand, for n = 100,000: n3 ÷ 6 ≈ 1.7 × 1014 checks is about 46 hours. n2 ÷ 2 = 5 × 109 steps is 5 seconds. 2n = 2 × 105 steps is 0.2 milliseconds.

Claim 1: "the window is n times faster than the double loop." Check: (n2 ÷ 2) ÷ 2n = n ÷ 4 = 25,000, not 100,000. Verdict: exaggerated by about 4 times.

Claim 2: "for problem 3, the window is 25,000 times faster." Richard Hamming, a mathematician known for quick checks, would ask if the numbers fit the real problem. LeetCode 3 allows about 95 different characters, so the double loop can stop each start after 95 steps: 9.5 million steps, about 50 times the window. Verdict: exaggerated by about 500 times. The big win comes when good stretches can be long.

Worked example 2: Minimum Window Substring (LeetCode 76)

Problem. Return the shortest stretch of s that contains every character of t, with repeats, or "" if there is none. For s = "ADOBECODEBANC" and t = "ABC", the answer is "BANC".

Test the mirror of Fact 3. For a shortest problem, a good window must stay good when it grows. Here it does: added letters cannot remove a letter of t.

A fast test. Keep one number, have: how many different letters of t have enough copies in the window. need is how many different letters t has. The window is good when have == need. have changes only when a letter's count crosses its target.

Each bar is one letter of t, and a blue bar has enough copies. The dashed line marks the shortest good window so far.

def minWindow(s, t):
    if not t or len(s) < len(t):
        return ""
    required = {}
    for c in t:
        required[c] = required.get(c, 0) + 1
    need = len(required)                  # different letters to satisfy
    window = {}
    have = 0
    best_l, best_len = 0, float("inf")
    l = 0
    for r, c in enumerate(s):
        window[c] = window.get(c, 0) + 1
        if c in required and window[c] == required[c]:
            have += 1                     # c just got enough copies
        while have == need:               # good: record, then shrink
            if r - l + 1 < best_len:
                best_l, best_len = l, r - l + 1
            window[s[l]] -= 1
            if s[l] in required and window[s[l]] < required[s[l]]:
                have -= 1                 # s[l] just fell below its target
            l += 1
    return s[best_l : best_l + best_len] if best_len != float("inf") else ""

The invariant here: when the shrink loop ends, the window is bad, and every good window that ends at r was recorded.

Worked example 3: Longest Repeating Character Replacement (LeetCode 424)

Problem. You can change at most k letters. Return the longest stretch that you can make into one letter. For "AABABBA" and k = 1, the answer is 4 ("AABA").

Find the rule. Keep the most common letter (count top) and change the others: length − top changes. The window is good when length − top ≤ k.

Test Fact 3. When the window grows, length goes up by 1 and top by 0 or 1. So length − top never goes down, and a bad window stays bad.

def characterReplacement(s, k):
    count = {}                            # notes: letter counts in s[l..r]
    l = 0
    best = 0
    for r, c in enumerate(s):
        count[c] = count.get(c, 0) + 1
        while (r - l + 1) - max(count.values()) > k:   # length − top > k: bad
            count[s[l]] -= 1
            l += 1
        best = max(best, r - l + 1)
    return best

Trace: the window grows to "AABA" (4 − 3 = 1 change, good, best 4). Adding B gives "AABAB" (5 − 3 = 2, bad). A goes out: "ABAB" (4 − 2 = 2, still bad). A goes out: "BAB" (good). max(count.values()) only reads the notes (26 letters at most), so the total is about 26 × 2n steps.

When the window gives a wrong answer

Fact 3 is not always true. Find the longest stretch with a sum of at most 4 in [5, −4, 3].

The window answers 2. But the full list has a sum of 4 and a length of 3. A negative number made a bad stretch good when it grew, so Fact 3 was false. For sums with negative numbers, use running totals (P2). Card 28 shows "sum exactly k".

How to recognize it

  • Substring, subarray, contiguous or window, with "longest" or "shortest".
  • A rule about the contents: no repeats, at most k different values, every letter of t, a sum limit with positive numbers.
  • The rule passes Fact 3 (longest) or its mirror (shortest).
  • A fixed size k, the simplest case: each step adds one item and removes one (exercise 2).
  • Not two pointers (P5). There, only the two end items are important. In a window, every item between the edges is important.

Common mistakes

  • Moving l without changing the notes. Remove s[l] from the notes first, then do l += 1.
  • The wrong shrink test. Longest: shrink while bad. Shortest: shrink while good.
  • No good window. If best_len is still infinity, return "". Do not slice with it.

Try it yourself

Do each one before you open the answer.

1. Type "pwwkew" into the first grid. Say each step before you click.

p, pw. Add w: bad. Remove p, then w. Then wk, wke. Add w: bad. Remove w: kew. Answer: 3.

2. Largest sum of 3 side-by-side numbers in [2, 1, 5, 1, 3, 2]

Add the new number and subtract the one that leaves: 8, then 7, 9, 6. Answer: 9, from [5, 1, 3].

3. Shortest stretch with a sum of at least 7 in [2, 3, 1, 2, 4, 3]

All numbers are positive, so the mirror of Fact 3 is true. [2, 3, 1, 2] = 8: record 4, remove 2. Add 4: record 4, remove 3, record 3, remove 1. Add 3: record 3, remove 2, record 2 ([4, 3]), remove 4. Answer: 2.

4. Longest stretch with at most 2 different characters in "eceba"

Notes: a count for each character. Delete a key when its count falls to 0, so len(count) is the number of different characters. e, ec, ece (3). Add b: three different, bad. Remove e (count 1): still bad. Remove c (count 0, delete): "eb". Add a: bad. Remove e: "ba". Answer: 3.

In the real world

A story from 1981. TCP, the part of the internet that delivers data in order, uses a sliding window. Inside it are the bytes that were sent but not yet confirmed. New bytes go in on the right until the window is full. Confirmed bytes leave on the left.

The first rules allowed 65,535 bytes at most. A round trip across the United States takes about 70 milliseconds, and the sender can send one window for each round trip: 65,535 ÷ 0.07 ≈ 936,000 bytes, or about 7.5 megabits, each second. In 1992, RFC 1323 added "window scaling", which lets the window grow to about 1 gigabyte. Claim: "without scaling, one connection across the US cannot go faster than about 7.5 megabits each second." Verdict: approximately accurate, because real round trips are about 60 to 80 milliseconds.

Rate limits ("100 requests in any 60 seconds") and moving averages (heart rate for the last 30 seconds) use the same shape.
