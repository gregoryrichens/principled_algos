Tree recursion

Most tree problems have a short solution, because you write the job of only one node: ask its two children, combine their answers, and report the result to its parent.

DRILLS.md is the practice file in this folder. Its Cards 16, 17 and 18 have drills for this page. You do not need them to read this page.

As if to a child

A big school wants to know how many staff work in it. The head teacher does not walk to every room to count. She asks the two deputies under her: "How many people work in your part of the school?" Each deputy asks the two teachers under him. Each teacher asks the two class helpers under her. A helper has nobody under her, so she says, "Just me. One."

Then the answers come back up. A teacher hears "1" and "1", adds herself, and says "3". A deputy hears "3" and "3", adds himself, and says "7". The head teacher hears "7" and "7", adds herself, and knows the answer: 15. Nobody counted the whole school. Each person did one small job: ask the people directly under you, add, and tell the person above you.

Messages can also go down. The head teacher tells each deputy, "Your part of the school can spend at most £100 on the trip." A deputy tells each of his teachers, "You can spend at most £50." A teacher can make the limit smaller for her helpers, but never larger. So each helper knows a limit that agrees with every person above her, and nobody had to look at the whole school.

The extended explanation

What a tree is

A tree here is like a family tree, drawn from the top down. Each box in it is a node. A node has a value and at most two children, called left and right. The node at the top is the root. A node with no children is a leaf. A tree where each node has at most two children is a binary tree, and all the trees on this page are binary trees.

In Python, each node is an object made from the class below. node.val is its value, and node.left and node.right are its children. A missing child is None.

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

LeetCode writes a tree as a list. It reads the tree row by row, from left to right, and writes null for a missing child. So [1, 2, 3, 4, 5] means this tree:

        1
       / \
      2   3
     / \
    4   5

The functions on this page get the root node (a TreeNode), not the list. LeetCode builds the nodes from the list for you.

Now the important fact. Put your hand over the root. What is left? Two smaller trees: one with 2 at the top, and one with 3 at the top. Each child is the root of its own smaller tree, called a subtree. A missing child is a tree too: the empty tree. So a question about a tree almost always breaks into the same question about two smaller trees. A function that answers a question by asking the same question about smaller parts is recursive.

Write the job of one node

Go back to the school. Each person did the same three things. First, a person with nobody below gave a fixed answer. Second, each person asked the people directly below. Third, each person combined those answers and told the person above. Here is a function that counts the nodes in a tree, in exactly that shape:

def count(node):
    if not node:                  # 1. the empty tree has no nodes
        return 0
    left = count(node.left)       # 2. ask the left child
    right = count(node.right)     #    and the right child
    return 1 + left + right       # 3. combine, and report up

One difference from the story. In the school, the helpers at the bottom gave the fixed answer, "one". The code goes one step further down. Below each leaf it asks the empty tree, and if not node is true only when node is None. The empty tree answers 0. Then a leaf works like every other node: 1 + 0 + 0 = 1. So the code needs only one fixed answer, for the empty tree, and no special rule for leaves.

Now look at one call only. It does not know the size of the tree or where in the tree it is, and it does not need to. It trusts its two children to give correct counts, and it adds 1 for itself.

Most people find this trust strange at first. So let us check that it is safe. The empty tree returns 0, and that is correct. A leaf gets 0 and 0 from its two empty children and returns 1, and that is correct too. Now take any node whose two children return correct counts. Then 1 plus those counts is a correct count for the node. So correct answers start at the bottom and climb up, one level at a time, to the root. This argument is called induction, and you use it each time you trust a recursive call.

So you do not need to follow all the calls in your head to write the code. You need to answer one question: "If my children give me correct answers, can I make my own correct answer?" But it helps to see the order of the calls one time, and we will do that below.

Worked example 1: report two facts up (LeetCode 543)

Diameter of Binary Tree (LeetCode 543). Return the length of the longest path between any two nodes. The length is the number of edges on the path (the lines between nodes). The path does not have to go through the root.

root = [1, 2, 3, 4, 5]      (the tree drawn above)
answer: 3                   the path 4 → 2 → 1 → 3 has 3 edges

The slow way. We need one more word first. The height of a tree is the number of nodes on the longest path from its root down to a leaf. The empty tree has height 0, and a single leaf has height 1. (Some books count height in edges, so a leaf has height 0. This page counts nodes, the same as the code.)

Now think about one node. Any path has one highest node. From there, the path goes down the left side, down the right side, or down both. We say the path bends at its highest node, even when it goes down only one side. The longest path that bends at a given node goes down to the deepest point on its left, and down to the deepest point on its right.

How many edges is that? The left height counts the nodes on the deepest path down the left side. Each of those nodes is joined to the node above it by one edge, so that half of the path has exactly as many edges as the left height. The same is true on the right. So the length of the path is the left height plus the right height. Compute that bend at every node, and keep the largest:

def height(node):
    if not node:
        return 0
    return 1 + max(height(node.left), height(node.right))

def diameter(node):
    if not node:
        return 0
    through_here = height(node.left) + height(node.right)
    return max(through_here, diameter(node.left), diameter(node.right))

Where the time goes. Each call to height walks the whole subtree under it, and diameter calls height on the children of every node. Follow node 4 in the tree above. diameter(2) visits node 4 once, to get the height of its left child. diameter(1) visits node 4 again, inside the height of node 2. So node 4 is visited two times, once for each of its two ancestors (2 and 1). In a tall tree, a node near the bottom has many ancestors, and it is visited again for each one.

Napkin math: how slow is slow?

Take the worst shape: a chain of n nodes, where each node has one child. At the top node, diameter measures the subtree of its child, which has n − 1 nodes. At the next node, it measures n − 2 nodes, and so on down to 1. The total is 1 + 2 + … + (n − 1), which is about n² / 2 visits. Each visit also makes a call on the empty child, so the number of function calls is about twice that: n².

For n = 10,000, that is 10,000 × 10,000 = 100,000,000 calls. Python makes about 10 million simple function calls per second, so the slow way takes about 100,000,000 / 10,000,000 = 10 seconds. The fix below makes about 2 calls per node: 20,000 calls, or about 2 milliseconds. (A chain this deep needs one change to Python's settings before it can run at all. The second napkin box explains why.)

Verdict: approximately accurate. On your computer, both times can be 2 or 3 times faster or slower. The ratio, about 5,000 to 1, stays the same. This is what O(n²) means for the slow way: double the nodes, and the work grows 4 times. The fix is O(n): double the nodes, and the work only doubles.

The fix. Look again at what the two functions need. diameter at a node needs the heights of its two children. height at a node also needs the heights of its two children. They ask the same question! So one walk can do both jobs, if each call reports both facts about its subtree.

So write one function, walk, that returns a pair for its subtree: the height and the diameter. The parent needs both. It needs the heights of its children to find the path that bends at itself. And it needs the diameters of its children, because the longest path in its subtree may not touch the parent at all. That path can lie fully inside one child's subtree.

So at each node, the diameter of the subtree is the largest of three numbers: the path that bends here (lh + rh), the longest path inside the left subtree (ld), and the longest path inside the right subtree (rd).

def diameterOfBinaryTree(root):
    def walk(node):                       # returns (height, diameter) of this subtree
        if not node:
            return 0, 0                   # the empty tree: no nodes, no edges
        lh, ld = walk(node.left)
        rh, rd = walk(node.right)
        height = 1 + max(lh, rh)          # what the parent needs to make longer paths
        diameter = max(lh + rh, ld, rd)   # bends here, or lies fully in one side
        return height, diameter
    return walk(root)[1]                  # the answer is the second number

A Python function can return two values at one time, as a pair: return height, diameter. The caller takes them apart with lh, ld = walk(node.left). At the end, walk(root)[1] takes the second value of the root's pair.

A node finishes only after both of its children finish. So on the tree [1, 2, 3, 4, 5], the nodes finish in this order: 4, 5, 2, 3, 1.

NodeLeft pair (lh, ld)Right pair (rh, rd)Bend here (lh + rh)Returns (height, diameter)
4(0, 0)(0, 0)0(1, 0)
5(0, 0)(0, 0)0(1, 0)
2(1, 0)(1, 0)2(2, max(2, 0, 0)) = (2, 2)
3(0, 0)(0, 0)0(1, 0)
1(2, 2)(1, 0)3(3, max(3, 2, 0)) = (3, 3)

Every node is visited one time, so the time is O(n).

walk reads only its argument, and it changes nothing outside itself. It answers one question about one subtree. Many solutions online, and Card 16 in DRILLS.md, do it another way. They keep the answer in a variable outside the function, with nonlocal or self.best, and change it from inside each call. Then the function returns one value and also changes another. That breaks command-query separation: a function should either answer a question or change something, not both. The pair version is just as fast, and you can test each call by itself.

Watch the computer run it

A computer cannot ask two children at the same time. It follows one call to its end before it starts the next. The widget below runs walk on a tree with 9 nodes. Press Step, and look at three things.

  • The order. The calls start down the left side first. But a node finishes only after both of its children finish. So the nodes finish children first, parent last: 8, 6, 4, 9, 7, 5, 2, 3, 1. This finish order is called post-order.
  • The stack of open calls. When a node calls a child, the node stops and waits with half of its work done. You can see that in the list, for example left = (3, 2), right = ?. The waiting calls make a pile, called the call stack. Only the call on top runs. The pile is never taller than the longest path from the root down: here 5 calls, for 9 nodes. (The calls on empty children start and end at once, so the widget does not show them. In real Python they add one more call at the deepest moment.)
  • The second number. Each node returns its own diameter: the largest of its bend and its children's diameters. Watch where the largest value first appears, and how it gets to the root.

Now you can see why each call must report two numbers. The longest path, 8 – 6 – 4 – 2 – 5 – 7 – 9, bends at node 2 and uses both of node 2's edges down. A path cannot split into branches, so at each node it uses at most two edges. To reach the root, this path would need a third edge at node 2, the edge up to node 1. So the root cannot make this path longer. What the root can use from node 2 is a path that goes straight down from node 2 on one side, and the longest such path is the height. So node 2 reports two different numbers: its height, 4, which the root uses to make new paths, and its diameter, 6. The root's own bend is only 4 + 1 = 5, so it returns max(5, 6, 0) = 6 as its diameter, unchanged from node 2.

What stays true

Each principle in this folder has an invariant: a sentence that is true at every step of the code. Here it is true each time a call returns:

When walk(node) returns, the whole subtree under that node is finished. It returns exactly the height and the diameter of that subtree, and nothing outside the call has changed.

So before you write any tree function, decide two things:

  1. What does the parent need from each call? Here, the height, to make longer paths.
  2. What does the problem ask for? Here, the diameter. If the two are different, each call returns both, as a pair.

Information goes two ways

In the diameter, all the information goes up. A node needs facts about its descendants, the nodes under it, and its children return those facts. But some questions need facts about the ancestors, the nodes above. A child cannot ask its parent anything. The parent calls the child, not the other way. So the parent must give those facts to the child when it calls it, as arguments.

So use this test on each new tree problem. If the answer at a node depends on what is under it, the children return it up. If it depends on what is above it, the parent passes it down. Some problems need both directions. For example, to count the nodes that have no larger value above them, each call gets the largest value so far from its parent (down) and returns the count for its subtree (up).

Worked example 2: pass the limits down (LeetCode 98)

Validate Binary Search Tree. In a binary search tree, each node follows one rule. Every value in its left subtree is smaller than the node, and every value in its right subtree is larger. Return whether a given tree follows the rule.

        8
      /   \
     4     12
    / \    / \
   2   9  10  14

answer: False      9 is in the left subtree of 8, but 9 is larger than 8

The trap. Compare each node with its parent only, and this tree passes: 4 < 8, 12 > 8, 2 < 4, 9 > 4, 10 < 12, 14 > 12. But the rule is about every node in the left subtree, not only the child. 9 breaks the rule with its grandparent, 8.

The fix. Each node must be inside a range that all its ancestors make together. We write a range as (4, 8), which means "larger than 4 and smaller than 8". The root has no ancestors, so its range is (−∞, ∞): any value. In Python, −∞ and ∞ are float("-inf") and float("inf").

Follow the ranges down to the 9. The root 8 passes (−∞, 8) to its left child, 4, because everything on its left must be smaller than 8. Then 4 passes (4, 8) to its right child: everything there must be larger than 4, and the limit 8 from above still applies. So the rule is: go left from a node, and its value becomes the new upper limit. Go right, and its value becomes the new lower limit. The other limit stays as it was, so the range can only get narrower as you go down. The parent passes the range to each child as two arguments, low and high:

def isValidBST(root):
    def valid(node, low, high):        # every value here must be between low and high
        if not node:
            return True
        if not (low < node.val < high):
            return False
        return (valid(node.left, low, node.val) and    # going left: the upper limit gets smaller
                valid(node.right, node.val, high))     # going right: the lower limit gets larger
    return valid(root, float("-inf"), float("inf"))

Python's and stops at the first False. So after one node fails, the code does not check the rest of the tree. One bad node is enough to give the answer.

Now try both checks in the widget. The marked node has a dashed ring. Move the slider to change its value, and find all the values that the range check accepts.

checked now passes fails the marked node

(The range check accepts only 5, 6 and 7.) Compare this code with height. Both handle None first. But two things changed. The information goes down, not up. And the node does its own check before it calls its children, where height called its children first. It must, because each child needs a range that the parent makes from its own value.

Worked example 3: report two numbers up (LeetCode 337)

House Robber III. The houses make a binary tree, and each node holds the money in one house. If a thief robs two houses that are directly joined (a parent and its child), the alarm goes off. Return the most money the thief can take.

        3
       / \
      2   3
       \   \
        3   1

answer: 7          rob the root 3, the lower 3 and the 1

You want each house to answer one question: "What is the most money in my subtree?" But that one number is not enough for the parent, because the parent has a choice to make. If the parent robs itself, it needs the best total of each child's subtree with that child skipped. If the parent skips itself, it needs the best total of each child's subtree with the child free to be robbed or not. One number cannot answer both questions. So each call returns two totals, one for each case:

  • rob_me: the best total if this house is robbed. Then both children must be skipped: node.val + skip_l + skip_r.
  • skip_me: the best total if this house is skipped. Then each child can take its better choice: max(rob_l, skip_l) + max(rob_r, skip_r).

Here rob_l and skip_l are the two totals from the left child, and rob_r and skip_r are the two from the right child. An empty child reports (0, 0). Here is the work from the bottom up:

Houserob_meskip_me
leaf 3 (under the 2)30
leaf 110
the 22 + 0 + 0 = 2max(0, 0) + max(3, 0) = 3
the upper right 33 + 0 + 0 = 3max(0, 0) + max(1, 0) = 1
root 33 + 3 + 1 = 7max(2, 3) + max(3, 1) = 6

To rob the root, the thief must skip both children. Their skip_me values are 3 and 1, so rob_me at the root is 3 + 3 + 1 = 7.

def rob(root):
    def go(node):                                      # returns (best if I rob this house, best if I skip it)
        if not node:
            return 0, 0
        rob_l, skip_l = go(node.left)
        rob_r, skip_r = go(node.right)
        rob_me = node.val + skip_l + skip_r            # robbing me means both children are skipped
        skip_me = max(rob_l, skip_l) + max(rob_r, skip_r)   # skipping me lets each child do its best
        return rob_me, skip_me
    return max(go(root))

At the end, max(go(root)) takes the larger of the root's two totals.

This is the same move as the diameter: decide what each node reports up before you write code. In both problems, the parent needs more than the final answer, so the report is a pair.

How deep the calls go

Napkin math: the size of the call stack

Each open call waits on the stack. So the memory that a tree function uses depends on the depth of the tree, not on its number of nodes. The depth is the number of levels, which is the same number as the height of the root.

Take a tree where every level is full. It doubles in size at each level: 1, 2, 4, 8 nodes, and so on. 220 = 1,048,576, so a tree like this with a million nodes has only about 20 levels. At most about 20 calls wait at the same time, which is far below Python's limit.

That limit: Python stops a program with a RecursionError after about 1,000 nested calls. A chain of n nodes has n levels, and many LeetCode tree problems allow up to 10,000 nodes. So a test shaped like a chain can stop your code.

Verdict: accurate. 1,000 is the default limit in Python (sys.getrecursionlimit() returns 1000). For deep trees, raise the limit at the start, for example with sys.setrecursionlimit(20000). Or use a loop that keeps its own list of nodes to visit, in place of the call stack. Card 30 in DRILLS.md shows how.

How to recognize it

Almost every binary tree problem uses this principle: depth, balance, paths, comparing two trees, mirroring a tree, building a tree, or turning a tree into text and back. To choose the shape of the code, apply the up-or-down test from above:

  • The answer at a node depends on its descendants, for example a height, the sum of a subtree, or "robbed or not". The children return it up.
  • The answer at a node depends on its ancestors, for example an allowed range, or the largest value on the path from the root. The parent passes it down as arguments.
  • The problem asks for the tree "level by level", or for "what you see from the right side". Here the easiest tool is a queue: a line where nodes join at the back and leave from the front, so they leave one level at a time (Card 18). Recursion can do it too, if you pass the level number down. A later principle, P13, uses the same queue to explore networks.

Common mistakes

  • Writing code before you decide what each call returns. Decide first, and write it down. A pair such as (is_balanced, height) is fine.
  • Forgetting the paths that do not touch the current node. The diameter of a subtree is max(lh + rh, ld, rd), not only lh + rh. Without ld and rd, a long path deep inside one side is lost before it gets to the root.
  • Comparing a node with its parent only. The search tree rule is about all the ancestors, so pass a range down.
  • Using recursion on a very deep tree. A chain of 10,000 nodes is deeper than Python's limit of about 1,000 nested calls. Raise the limit, or use a loop (Card 30).

In the real world

Every screen you look at. A web page is a tree. The page holds sections, a section holds paragraphs, and a paragraph holds words. Before the browser can draw anything, it must find the size and place of each box. It does this with both directions of this page. The width that a box can use comes down from its parent: a column cannot be wider than its page. The height of a box goes up from its children: a paragraph is as tall as its lines of text. Google's Flutter toolkit, which draws the screens of many phone apps, tells its users this rule in a few words: limits go down, sizes go up, and the parent decides where each child goes. The width works like the range in isValidBST: each parent passes a limit down, and a child can only make it smaller. The height works like the height in walk: each box reports its size up, and its parent combines the sizes of its children. So one walk of the tree uses both directions of this page.

Git. Git gives each file a fingerprint: a short code calculated from its contents. A folder's fingerprint is calculated from the fingerprints of everything in it. So one change in one file changes the fingerprint of each folder above it, up to the top. To find what changed between two versions, git compares the two top fingerprints. Where they are equal, it skips the whole subtree. Where they differ, it goes down into the children. One small piece of information, reported up from each node, saves git from looking at almost all the files.
