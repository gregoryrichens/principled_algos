Principled Algos · Principle 6 of 18

The Stack

Keep the items that still wait for an answer in a pile. A new item answers the waiting items at the top that it beats. Then it waits too.

As if to a child

Think of a pile of plates. You put plates on the top and take them off the top, never from the middle. That is a stack: the last thing in is the first thing out.

Now a game. Each day, you write the temperature on a card. You want to know, for each day, how many days you wait until a warmer day. When a new day comes, look at the card on the top of the pile. If that card is colder than today, today is its warmer day. Write the answer on the card and take it off. Look at the next card. Stop when the top card is not colder. Then put today's card on the pile, because today must wait too. Cards that stay on the pile at the end never got a warmer day.

The extended explanation

Start from what is true

Take the temperature game as the problem. It is Daily Temperatures, problem 739 on LeetCode, a website of practice problems for coding interviews. The input is a list of temperatures, one per day. For each day, return how many days until a warmer day, or 0 if no warmer day comes.

temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
answer       = [ 1,  1,  4,  2,  1,  1,  0,  0]

For example, day 2 (75°) waits 4 days for day 6 (76°). The slow way: from each day, look forward until a warmer day appears. Now look for facts we can be sure of.

  • Fact 1. Turn the question around. A day learns its answer only when a warmer day arrives. So let each new day look back and tell the waiting days "I am your answer".
  • Fact 2. A new day answers every waiting day that is colder than it. All of those days leave the waiting group at once.
  • Fact 3. So the waiting days are always in order. After today answers all colder waiting days, every day still waiting is at least as warm as today. Then today joins as the coldest. From oldest to newest, the temperatures never go up.

Fact 3 is the key. The newest waiting day is the coldest. If today is not warmer than it, today is not warmer than any older one. So today only checks the newest, then the next newest, and stops at the first day that is not colder. "Add at the top, check the top, remove from the top" is exactly a stack.

Watch the pile

Each bar is one day. The pile on the right is the stack of days that still wait, with the newest on top. Each click does one small action: check the top, remove a day and write its answer, or add today.

Try "Long cold spell". The pile grows, then one hot day clears it in one burst. That looks expensive. But count the work. Each day goes onto the stack one time and comes off at most one time. Each check of the top either pops a day, or stops the loop for today. So with n days there are at most n pops, and at most n checks that stop, which is at most 2n checks in total, whatever the order of the days. On 8 days both methods do about the same work. The gap grows with the length of the list.

The sentence that keeps the code correct

Of the days seen so far, the stack holds exactly the days with no warmer day yet, and their temperatures never go up from bottom to top.

This is the invariant: a statement that is true after every step. A stack kept in order like this is a monotonic stack: "monotonic" means "goes in one direction only".

Worked example 1: Daily Temperatures (LeetCode 739)

def dailyTemperatures(temperatures):
    answer = [0] * len(temperatures)
    waiting = []                        # positions of days with no warmer day yet
    for today, temp in enumerate(temperatures):
        while waiting and temperatures[waiting[-1]] < temp:
            day = waiting.pop()         # today is the first warmer day after `day`
            answer[day] = today - day
        waiting.append(today)           # today waits too
    return answer                       # days left on the stack keep 0

In Python, a list is a stack. append adds to the top, pop() removes from the top, and waiting[-1] reads the top. enumerate gives each item with its position. Three details matter:

  • Store positions, not temperatures. The answer is a distance in days, so you need to know when each day was. You can always look up its temperature.
  • Use <, not <=. An equal temperature is not warmer.
  • Deal with what is left. Days still on the stack at the end never found a warmer day. Here their answer stays 0.

Napkin math: is it really faster?

Count "checks": one comparison of two temperatures. Assume a computer does about 109 checks each second. Take n = 106 readings. (A sensor that reads once each second makes 106 readings in 106 ÷ 86,400 ≈ 12 days.)

Row 1. Each reading scans to the end of the list, so the scans are n − 1, n − 2, ... 1 long. They add up to about n × n ÷ 2.

Row 2. When all values are different, a warmer reading usually comes soon. On average a scan is about ln n long. (ln is the natural logarithm, and ln 106 ≈ 14.) A test program that counts the checks agrees.

Row 3. Real readings are often rounded to whole degrees, so many are equal. Equal is not warmer. Say 20 values are possible. Then about 1 reading in 20 has the highest value, and it never finds a warmer reading. Each of those n ÷ 20 readings scans to the end, an average of n ÷ 2 checks. That is n ÷ 20 × n ÷ 2 = n × n ÷ 40.

So the statement "the slow way takes minutes on a million readings" is accurate for row 1, exaggerated about 36,000 times for row 2 (500 s ÷ 0.014 s), and close to true for row 3, which looks the most like real data. The stack does not care. It always stays under 2n checks. That guarantee is its real value.

The other kind of stack problem: matching

Valid Parentheses (LeetCode 20). A string contains only ( ) [ ] { }. Return whether every bracket closes with the correct type, in the correct order. "([]{})" is valid. "([)]" is not.

Start from what is true. A closing bracket must close the most recent bracket that is still open. "Most recent, still waiting" is again the top of a stack. The open brackets wait for their answer, and the answer is the closing bracket.

String:

Teal: the bracket read now. Grey: brackets already read. Amber boxes: open brackets that wait on the stack. Blue outline: the top matches. Red: the step that fails.

def isValid(s):
    match = {")": "(", "]": "[", "}": "{"}
    stack = []                          # open brackets not yet closed
    for c in s:
        if c not in match:
            stack.append(c)             # an open bracket waits
        elif not stack or stack[-1] != match[c]:
            return False                # nothing to close, or the wrong type
        else:
            stack.pop()                 # closes the most recent open bracket
    return not stack                    # anything left never closed

The first preset is valid. The string can fail in three ways, and each of the other presets shows one. ([)]: a closing bracket meets the wrong type on top. ()): a closing bracket finds an empty stack. {[()]}(: an open bracket is still on the stack at the end.

Worked example 2: Largest Rectangle in Histogram (LeetCode 84)

Problem. heights[i] is the height of a bar of width 1. Return the area of the largest rectangle that fits inside the bars. For [2, 1, 5, 6, 2, 3] the answer is 10: the bars of height 5 and 6 hold a rectangle 5 high and 2 wide.

Build it from facts. Take the best rectangle. Its height is the height of the shortest bar under it. Call that bar B. Now take the widest rectangle that has B's full height. It stretches left and right from B until it meets a shorter bar. It contains the best rectangle, so it is at least as big. So we lose nothing if we check only one rectangle per bar: the widest one at that bar's full height. To find it, each bar needs its nearest shorter bar on the right and on the left.

The right edge. The stack holds bars that have not found their right edge yet. When a shorter bar arrives, it is the right edge of every taller bar on the stack. Pop each one and measure its rectangle. Note the direction. Here we look for the next shorter bar, so the stack keeps heights that never go down from bottom to top. Daily Temperatures looks for the next warmer day, so its stack never goes up. This direction is the most common bug.

The left edge. The stack stores pairs: (start, height). The start is the leftmost position the bar's rectangle can cover. When a new bar pops some taller entries, its rectangle can also cover all the positions those entries covered, because those bars were all taller. So its start becomes the start of the last entry it popped. If it pops nothing, its start is its own position.

Teal: the bar that arrives now. Blue fill: the rectangle measured now. Dashed box: best so far. Blue outline on the stack: the top under check. Entries read (start, height). At the end, position 6 means "one past the last bar". The status line then checks the answer against the slow way, which tries every start and end.

def largestRectangleArea(heights):
    best = 0
    stack = []                          # (start, height), heights go up
    for i, h in enumerate(heights):
        start = i
        while stack and stack[-1][1] > h:   # [1] is the height of the top pair
            s, height = stack.pop()     # bar i is the first shorter bar on its right
            best = max(best, height * (i - s))
            start = s                   # the new bar stretches back to here
        stack.append((start, h))
    for s, height in stack:             # never met a shorter bar: stretch to the end
        best = max(best, height * (len(heights) - s))
    return best

How to recognize it

  • "For each item, find the next (or previous) item that is bigger (or smaller)."
  • "How long until ...", "how far back until ...".
  • Something stretches until a smaller item blocks it, like the rectangle.
  • Matching or nesting: brackets, HTML tags.
  • "Undo the most recent action first."

The test question: does a new item answer the most recent waiting items first? If it answers the oldest first, use a queue (first in, first out).

Temperatures [70, 68, 72, 71, 75]. Trace the stack on paper. Write the stack after each day and the answer list at the end.

Day 4 (75): pop day 3 (wait 1), pop day 2 (wait 2), push. Stack [4]. Day 4 is left, so it gets 0. Answer: [2, 1, 2, 1, 0].

Harder: Evaluate Reverse Polish Notation (LeetCode 150)

The input ["2", "1", "+", "3", "*"] means (2 + 1) × 3. Each operator uses the two numbers just before it. Push each number. For an operator, pop two numbers, apply the operator, and push the result. Stack: [2], [2, 1], [3], [3, 3], [9]. The answer is 9. Note: the first pop gives the right-hand number. For "-" and "/", the order matters. Also, the problem rounds division toward zero. In Python, // rounds down, so -7 // 2 gives −4, not −3. Use int(a / b) instead.

In the real world

A story from 1957. In Germany, Friedrich Bauer and Klaus Samelson wanted a machine to read formulas such as (2 + 1) × 3. Brackets inside brackets made this hard. Their solution kept each unfinished part in a pile and finished the newest part first. They patented it as the Kellerprinzip, the "cellar principle": the last thing you put in the cellar is the first thing you get out.

  • Every running program. When function A calls function B, A must wait until B is done. If B calls C, C finishes first, then B, then A. The computer keeps the waiting functions on the call stack. A "stack overflow" error means this pile became too tall.
  • Undo and Back. An editor pushes each change. Undo pops the most recent one. The browser Back button works the same way.
  • Code checkers. A compiler (the program that turns code into a running program) checks that each { closes in the correct order. That is Valid Parentheses. A browser also keeps a stack of open HTML tags, but it repairs mistakes instead of rejecting the page.
  • Stock charts. "For how many days in a row has the price been at or below today's price?" is the stock span problem. Each day looks back for the most recent higher price. A monotonic stack of earlier prices answers it in one pass, the same way it answers Daily Temperatures.

In each case, the most recent unfinished item comes next. A stack finds it in one step.
