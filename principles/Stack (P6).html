Principled Algos · Principle 6 of 18

The Stack

Keep the unfinished items in a pile. Settle them from the top.

As if to a child

Think about a pile of plates. You put a clean plate on the top, and you take a plate from the top. A pile that works like this is a stack.

Now a game. Children come into a room one at a time. Each child asks: “Who is the first child after me that is taller than me?” Children with no answer stand in a line. A new child looks at the last child in the line. If that child is shorter, the new child says, “I am your answer,” and that child sits down. At the first child who is not shorter, the new child stops and joins the end of the line. The line is always tallest at the front. So the new child never walks the full line. In computer terms, the line is the stack: its end is the top. Each child joins the line once and leaves it once.

The extended explanation

Start from what is true

Some items cannot have their answer when they arrive. Ask two questions:

  • Does each item wait for a later item to settle it?
  • Does the most recent unanswered item always settle first?

If both answers are yes, keep the unanswered items in a stack. The top is always the next item to settle. You only look at the top. Example 1 below answers yes to both questions.

What a stack is

A stack is a list where you add and remove items only at the top. A Python list does this:

stack = []
stack.append(5)   # push: put 5 on the top
stack.append(9)   # push: put 9 on the top
stack[-1]         # peek: look at the top, which is 9
stack.pop()       # pop: remove the top, which is 9

Each operation takes the same short time, for 3 items or 3 million.

Worked example 1: Daily Temperatures (LeetCode 739)

temperatures[i] is the temperature on day i. For each day, find how many days you must wait for a warmer day. If no warmer day comes, the answer is 0.

temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
answer       = [ 1,  1,  4,  2,  1,  1,  0,  0]

Day 2 is 75°. The next warmer day is day 6, at 76°. So day 2 waits 4 days.

The slow way. Each day looks forward, one day at a time, until it finds a warmer day.

answer = [0] * len(temperatures)
for i in range(len(temperatures)):
    for j in range(i + 1, len(temperatures)):
        if temperatures[j] > temperatures[i]:
            answer[i] = j - i
            break

Suppose every day is colder than the day before. Then each day looks at all the days after it. For 8 days, that is 7 + 6 + … + 1 = 28 comparisons. For n days, it is about n²/2.

Turn the question around

The slow way asks, “When does my warmer day come?” Ask the opposite: “Which old days does a new day answer?”

A new day answers every unanswered day that is colder than it. Now look at the unanswered days. From oldest to newest, they never go up (equal values can stay side by side). Why? When a day arrives, all colder days at the end of the line receive their answer and leave. So each older day that stays is at least as warm.

This shape is the trick. The new day compares itself with the newest unanswered day first. If that day is colder, it has its answer and leaves. Then the new day checks the next one. At the first day that is not colder, it stops. All days further back are warmer still. Add at the end, look at the end, remove from the end: that is a stack.

def dailyTemperatures(temperatures):
    answer = [0] * len(temperatures)
    waiting = []                          # positions of days with no warmer day yet
    for today, temp in enumerate(temperatures):
        while waiting and temperatures[waiting[-1]] < temp:
            day = waiting.pop()           # today is the first warmer day after `day`
            answer[day] = today - day
        waiting.append(today)             # today waits too
    return answer                         # days still waiting keep the answer 0

There is a loop inside a loop, but count the work. Each day goes onto the stack once. Each day comes off the stack once at most. So the inner loop pops at most n times in total. Each comparison either pops a day or stops the loop for today, so there are at most 2n comparisons. In Big-O terms the work is O(n): it grows in proportion to n. The slow way is O(n²).

The stack holds positions because the answer is a number of days.

The sentence that keeps the code correct

The stack holds exactly the days that have no warmer day yet, and their temperatures never go up from bottom to top.

The second part makes the top the coldest unanswered day. If today is not warmer than the top, it is not warmer than any day below. So you stop. A stack that you keep in order like this is a monotonic stack: it always goes in one direction.

Napkin math: is it really faster?

On LeetCode, the list can have 100,000 days. Use the worst list: each day colder than the day before.

(10⁵)² ÷ 2 = 5 × 10⁹slow way: comparisons
≈ 10⁷ per secondsimple Python loop steps, a usual estimate
5 × 10⁹ ÷ 10⁷ = 500 sslow way: about 8 minutes
2 × 10⁵ ÷ 10⁷ = 0.02 sstack way: at most 2n comparisons

I tested these estimates on a real computer. Python did 1.6 × 10⁷ comparisons per second, so the slow way needs about 5 minutes. The stack way took 0.009 seconds. Verdict: the napkin numbers are approximately accurate, within a factor of about two. “O(n²) becomes O(n)” is accurate: here it is about 30,000 times faster.

Which way must the stack go?

Daily Temperatures asks for the next larger item. Other problems ask for the next smaller item, or the previous one. There are two rules.

  • Next: the stack holds items that wait for an answer. A new item answers each item it pops.
  • Previous: the stack holds items that can still be an answer. Pop each item that the new item hides: if the new item is at least as large, no later item can prefer the old one. The top that stays is the new item’s answer.

For strict “larger”, an equal item is not an answer, so a “previous” problem pops it too (<=). An empty stack means no answer: use the problem’s default value.

Worked example 2: brackets inside brackets (Valid Parentheses, LeetCode 20)

A string has only the characters ()[]{}. Return True if each bracket closes with the correct type, in the correct order. "([]{})" is valid. "([)]" is not.

The two questions still work. An opening bracket waits for a later closing bracket. A closing bracket must close the most recent bracket that is still open. “Most recent, still open” is the top of a stack.

def isValid(s):
    match = {")": "(", "]": "[", "}": "{"}
    stack = []                            # opening brackets not closed yet
    for c in s:
        if c not in match:
            stack.append(c)               # an opening bracket: it waits
        elif not stack or stack[-1] != match[c]:
            return False                  # nothing to close, or the wrong type
        else:
            stack.pop()                   # closes the most recent open bracket
    return not stack                      # anything left never closed

A calculator. In Reverse Polish Notation (LeetCode 150), ["2", "1", "+", "3", "*"] means (2 + 1) × 3 = 9. Push each number. An operator pops two numbers and pushes the result.

def evalRPN(tokens):
    stack = []
    for t in tokens:
        if t in "+-*/":
            b = stack.pop()               # the second number comes off first
            a = stack.pop()
            if t == "+": stack.append(a + b)
            elif t == "-": stack.append(a - b)
            elif t == "*": stack.append(a * b)
            else: stack.append(int(a / b))  # the problem says: round toward zero
        else:
            stack.append(int(t))
    return stack[0]

Worked example 3: Remove K Digits (LeetCode 402)

Problem. num is a string of digits that spells a whole number, and k is how many digits you must delete. Delete exactly k digits so that the number left over is as small as possible. Return it as a string. It must have no leading zeros, and if nothing is left, return "0".

num = "1432219", k = 3
answer: "1219"        # delete 4, 3 and one of the 2s

num = "10200", k = 1
answer: "200"         # delete the 1; "0200" becomes "200" once the leading zero is dropped

num = "10", k = 2
answer: "0"           # everything is deleted

Trying every way to choose which digits to delete is far too slow. Think about what makes a number small instead: the leftmost digits matter most. Walk from left to right. If a digit is bigger than the digit right after it, deleting the bigger one makes the number smaller, because the smaller digit slides into its place. For example, in "1432219" the 4 is followed by a 3, and "132219" is smaller than "1432219".

That is a pile of unfinished decisions again. Keep a stack of the digits you are keeping so far. For each new digit d: while you still have deletions left (k > 0) and the top of the stack is bigger than d, pop it (that is one deletion). Then push d. Two cleanups at the end: if deletions are left over (the digits only ever went up, like "12345"), delete from the end, because the biggest digits sit there. Then strip leading zeros, and return "0" if nothing is left.

Trace for "1432219" with k = 3:

The stack spells 1219. Equal digits stay (the test is strictly “bigger”), because deleting one of two equal digits changes nothing at that spot.

def removeKdigits(num, k):
    stack = []                                  # digits we are keeping, left to right
    for d in num:
        while k > 0 and stack and stack[-1] > d:
            stack.pop()                         # a bigger digit just before a smaller one: delete it
            k -= 1
        stack.append(d)
    if k > 0:                                   # digits only rose, so the biggest are at the end
        stack = stack[:-k]
    return "".join(stack).lstrip("0") or "0"    # drop leading zeros; "0" if nothing is left

For "10200" with k = 1: the 0 is smaller than the 1 before it, so the 1 is popped (k becomes 0). The rest are pushed, giving "0200", and lstrip("0") leaves "200".

How to recognize it

  • “For each item, find the next (or previous) item that is larger (or smaller).”
  • “How long until …”, “how far back until …”.
  • “Largest rectangle” in bars (a Hard, for later).
  • Pairs inside pairs: brackets, HTML tags, expressions.

Common mistakes

  • < or <= in the pop condition. This decides equal values. In Daily Temperatures, an equal day is not warmer, so pop only on <.
  • The items left at the end. They never found an answer. Some problems want 0 for them; others want a default such as −1. Decide before you code.

Try it yourself

1. Next larger value: [2, 1, 2, 4, 3]

For each item, give the next larger value, or −1 if there is none.

Answer: [4, 2, 4, -1, -1]. Use the Daily Temperatures code, but record the value, not the distance.

2. Stock span (LeetCode 901): prices [100, 80, 60, 70, 60, 75, 85]

The span of a day is the number of days in a row, back from today, with a price at or below today’s price. Give each span.

Answer: [1, 1, 1, 2, 1, 4, 6]. This is “previous larger”: the span is today’s position minus the position of the previous higher price. If there is none, the span is today’s position + 1.

def spans(prices):
    stack, out = [], []                   # positions; prices go down, bottom to top
    for i, p in enumerate(prices):        # enumerate gives (position, value)
        while stack and prices[stack[-1]] <= p:
            stack.pop()                   # hidden by today: never an answer again
        out.append(i - stack[-1] if stack else i + 1)
        stack.append(i)
    return out
3. Which are valid: "{[]}(", "(]", ")("?

Answer: none of them. "{[]}(" leaves ( on the stack. "(]" has the wrong type on the top. ")(" closes before anything opens.

4. Next smaller value: [4, 5, 2, 10, 8]

For each item, give the next smaller value, or −1 if there is none.

Answer: [2, 2, -1, 8, -1]. Use the same code as problem 1, but pop while the top is larger than the new item.

In the real world

Every program you run uses a stack. When function A calls function B, the computer must remember where to go back to in A. B can call C, and C can call D. The return points come back in the opposite order: last in, first out. In February 1946, Alan Turing put this into his design for the ACE computer. He called the two operations BURY and UNBURY. Today the name is the call stack. Python stops at 1,000 nested calls by default.

Calculators and compilers. In 1955, Friedrich Bauer and Klaus Samelson used a stack to change formulas into machine steps. They called it the Kellerprinzip, the “cellar principle”. Python still does this. It changes a + b * c into the Reverse Polish steps below, and runs them on a stack, as evalRPN does.

LOAD_NAME  a       # push a
LOAD_NAME  b       # push b
LOAD_NAME  c       # push c
BINARY_OP  *       # pop c and b, push b * c
BINARY_OP  +       # pop b * c and a, push the sum

Why it is valuable. A stack changes a search inside a search into one pass. Each item costs one push and one pop, and the memory is at most one slot for each item.

Largest Rectangle in Histogram (LeetCode 84)

heights[i] is the height of a bar 1 unit wide. Find the area of the largest rectangle that fits inside the bars.

heights = [2, 1, 5, 6, 2, 3]
answer: 10        # bars of height 5 and 6 hold a rectangle 5 high and 2 wide

Start from what is true. In the best rectangle, at least one bar touches the top edge. If no bar touched it, you could make the rectangle taller. So try each bar as the bar that sets the height. Its rectangle stops at a shorter bar on each side. So each bar needs its nearest shorter bar on each side: “next smaller” and “previous smaller” from the table.

Keep a stack of bars with no right edge yet. Their heights go up from bottom to top. When a shorter bar arrives, it is the right edge for each taller bar on the top. Pop each one and measure: height × (position of the shorter bar − start).

The hard part is the start, the left edge. The bars on the stack go up in height, so the entry below a bar is its previous smaller bar. A bar’s start is just after that shorter bar. A new short bar can reach back over the taller bars it pops, so it takes the start of the last bar it popped. Each stack entry is a pair: (start, height). An equal bar does not pop: the older one stays and reaches further to the right later.

def largestRectangleArea(heights):
    best = 0
    stack = []                            # (start, height), heights go up
    for i, h in enumerate(heights):
        start = i
        while stack and stack[-1][1] > h:
            s, height = stack.pop()       # bar i is the first shorter bar to its right
            best = max(best, height * (i - s))
            start = s                     # the new bar can reach back to here
        stack.append((start, h))
    for s, height in stack:               # never met a shorter bar: go to the end
        best = max(best, height * (len(heights) - s))
    return best

Bars still on the stack at the end reach to the right end.
